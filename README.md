# ⛏️ CRAFT & SHARE

ブラウザ上で遊べる、複数人で同じ世界を共有する3Dサンドボックスゲームです。  
ワールド内でブロックを自由に設置・破壊して建築を楽しめるほか、リアルタイムチャットやコミュニティ掲示板、ブロックの面に貼れる「ワールド内メモ」を通じて、同じワールドを訪れたプレイヤー同士でコミュニケーションを取ることができます。

- **公開URL**: https://craft-and-share.onrender.com

## ✨ 主な機能

### 1. 3Dワールドの移動・ブロックの設置と破壊
- **8種類のブロック**: 草・土・石・木・砂・ガラス・葉・レンガをホットバー（`1`〜`8`キーまたはマウスホイール）で切り替えて設置・破壊できます。
- **建築補助・移動制御**:
  - ブロック上面の端を狙った際の水平方向へのエッジ設置補助、および見下ろし時の足場設置補助。
  - しゃがみ（`Shift`）移動時の足場外への落下防止処理。
  - ステージ外（`y < -100`）へ落下した際の安全な地表座標への自動リスポーン。

### 2. 複数プレイヤーによるリアルタイム共有
- **マルチプレイ同期**: 同じワールドに参加している他プレイヤーの位置・視線方向をリアルタイムに同期し、色分けされた3Dボクセルアバターと頭上ネームプレートを表示します。
- **オンライン状況表示**: 画面左上のHUDに現在ワールドに参加中のプレイヤー一覧と人数を表示し、入退室時にはトースト通知を表示します。

### 3. プレイヤー名・チャット
- **プレイヤー名設定**: 初回アクセス時にランダムな名前（`Player-XXXX`）を自動生成し、画面右上から1〜20文字でいつでも変更可能です。変更した名前はブラウザの `localStorage` に保存され、次回アクセス時にも維持されます。
- **リアルタイムチャット**: ワールド内のプレイヤー同士で最大200文字のメッセージをやり取りでき、後から参加したプレイヤーにもワールドごとの直近履歴（最大50件）が表示されます。

### 4. ワールドのデータ保存・読み込み
- **マルチワールド管理**: タイトル画面で登録済みワールドの一覧（ブロック数・最終更新日時）を確認し、好きなワールドに参加できます。
- **新規ワールド作成**: 1〜50文字のワールド名を指定して新しいワールドを作成できます。作成時には24×24の初期地形（丘・岩場・木ブロック）が自動生成されDBに保存されます。
- **ワールド削除**: ワールドを作成したブラウザにのみホスト認証キーが保存され、デフォルトワールド以外で参加中プレイヤーが0人の場合に限り、ワールド名の一致確認を経て削除できます。

### 5. コミュニティ掲示板（Community Board）
- ワールド内のスポーン地点近くに設置された3Dの木製掲示板をクリックすると、掲示板モーダルが開きます。
- **カテゴリ別投稿**: 「交流」「お知らせ」のカテゴリを選択して最大300文字のメッセージを投稿・閲覧でき、タブで絞り込み表示が可能です（1ワールド最大200件保持・最新50件取得）。
- **投稿の削除**: 投稿したブラウザの認証キーと一致する投稿のみ、削除ボタンが表示されます。

### 6. ワールド内メモ機能
- 任意のブロックの面（上下左右前後の6面）に照準を合わせて `M` キーを押すと、その面にメモ用紙オブジェクトを貼り付けることができます（最大150文字、1ワールド最大100件まで）。
- 貼られたメモを左クリックすると、投稿者名・投稿日時・本文をモーダルで閲覧できます。
- メモが貼られている面のすぐ手前には新しいブロックを設置できないよう制限しており、メモがブロックで埋もれるのを防いでいます。
- メモを作成したプレイヤー本人（同一ブラウザの認証キーかつ同一プレイヤー名）のみ削除可能です。

## 🔧 技術的な実装のポイント

### 1. Babylon.js による3D描画と最適化
- **インスタンス描画による負荷軽減**: 不透明ブロックは種類ごとのベースメッシュから `createInstance()` でインスタンス生成し、ドローコールを抑えています（草ブロックは `MultiMaterial` と `SubMesh` で上面・側面・下面を塗り分け）。
- **ガラスブロックの隣接面カリング**: 半透明のガラスブロックは、隣接する6方向に他のブロックが存在する場合に該当面の頂点インデックスを除外（` applyGlassIndices`）し、透明メッシュ同士の重なりによる描画の乱れと負荷を軽減しています。
- **レイキャストと移動補間**: `scene.pickWithRay` を用いてブロック・掲示板・メモの照準判定および接地判定を行い、他プレイヤーのアバター移動・回転には毎フレーム線形補間（`Vector3.LerpToRef` / 角度補間）を適用してカクつきを抑えています。

### 2. Socket.IO によるリアルタイム通信と楽観的更新
- **Roomによるワールド分離**: サーバー側で `world:<worldId>` のRoomに分けてイベントを配信し、別ワールドの通信が混ざらない構成にしています。
- **移動パケットの間引き送信**: クライアント側で送信間隔（約50ms / 20Hz）と移動・回転量の閾値を設け、静止時や微小な変化での不要な通信を抑制しています。
- **ブロック操作の楽観的更新（Optimistic UI）**: ブロックの設置・破壊時はサーバー応答を待たずにクライアント画面へ即時反映しつつ、`operationId` で保留操作を管理しています。サーバー側でエラーが発生した場合やタイムアウト（8秒）時には元の状態へ自動でロールバックします。

### 3. Express によるAPI・静的ファイル配信と単一サーバー構成
- REST API（`GET /api/worlds`, `POST /api/worlds`, `DELETE /api/worlds/:worldId`, `GET /api/world`, `GET /health`）でワールド操作とヘルスチェックを提供します。
- 開発環境では Vite のプロキシ機能で `/api` と `/socket.io` をバックエンド（ポート3000）へ転送し、本番環境（Render）では単一のHTTPサーバー上で Express が `dist/` の静的配信と Socket.IO のWebSocket通信をまとめて処理します。

### 4. PostgreSQL（Neon）によるデータ永続化と整合性管理
- `worlds`、`blocks`、`board_posts`、`world_memos` の4テーブルでデータを管理しています。
- `blocks` テーブルには複合主キー `(world_id, x, y, z)`、`world_memos` テーブルにはユニークインデックス `(world_id, x, y, z, face)` を設定し、同一座標への重複ブロックや同一ブロック面への重複メモをDBレベルでも防止しています。
- 各子テーブルは `worlds(id)` に対して `ON DELETE CASCADE` の外部キー制約を持ち、ワールド削除時に関連データが一括で整合性を保って削除されます。
- 初回ワールド生成時や掲示板・メモの更新時には、トランザクション（`BEGIN`〜`COMMIT` / `ROLLBACK`）と行ロック（`SELECT ... FOR UPDATE`）を使用して競合を防いでいます。

### 5. サーバー側での入力検証・直列化・権限管理
- **座標単位の非同期キュー**: 同一ワールド・同一座標へのブロック操作は `enqueueBlockOperation` によってPromiseチェーンで直列化し、同時リクエスト時のDB競合を防止しています。
- **バリデーションとレート制限**: ブロック座標の範囲・ブロック種別・文字数制限・面の向きなどをサーバー側で検証し、チャット（500ms）・掲示板（3秒）・メモ（2秒）にはソケット単位のクールダウンを設けています。
- **ハッシュ化キーによる削除認可**: ログイン機能を設けない代わりに、クライアント側で生成した乱数キーをサーバー側で SHA-256 ハッシュ化してDBに保存し、削除リクエスト時には `crypto.timingSafeEqual` で比較することで、作成者以外の削除を防いでいます。

## 🚀 起動方法

### 必要な環境
- **Node.js**: v18 以上推奨（開発環境: v24）
- **PostgreSQL**: ローカルの PostgreSQL または [Neon](https://neon.tech/) などのクラウド PostgreSQL

### 1. パッケージのインストール
```bash
npm install
# または
npm ci
```

### 2. 環境変数（`.env`）の設定
プロジェクトルートの `.env.example` をコピーして `.env` を作成し、PostgreSQL の接続文字列を設定してください。

```env
PORT=3000
DATABASE_URL=postgresql://username:password@your-db-host.neon.tech/neondb?sslmode=require
```

### 3. データベースの準備
- **既存DBを使う場合**: 手動のSQL実行は不要です。サーバー起動時に不足しているカラムやテーブル（`board_posts`, `world_memos`）が自動マイグレーションで安全に追加されます。
- **新規（空の）DBを使う場合**: 初回のみ `server/schema.sql` を実行して基本テーブル（`worlds`, `blocks`）を作成してください。
  - ※ `server/schema.sql` には初期化用の `DROP TABLE` が含まれているため、**すでにデータが入っているDBには実行しないでください。**

### 4. 開発環境での起動
バックエンドサーバーと Vite 開発サーバーをそれぞれ起動します。

```bash
# ターミナル1: バックエンドサーバー起動 (http://localhost:3000)
npm run server

# ターミナル2: フロントエンド開発サーバー起動 (http://localhost:5173)
npm run dev
```
ブラウザで `http://localhost:5173` にアクセスするとゲームが起動します。

### 5. 本番ビルド・起動方法
フロントエンドを `dist/` にビルドし、Express サーバー単体で画面配信と API / Socket.IO を起動します。

```bash
# フロントエンドのビルド
npm run build

# 本番サーバーの起動 (http://localhost:3000)
npm start
```

## 🎮 操作方法

| 操作内容 | キー / マウス操作 |
| :--- | :--- |
| **移動** | `W` `A` `S` `D` |
| **視点操作** | マウス移動（画面クリックでポインターロック） |
| **視点操作解除 / モーダルを閉じる** | `ESC` |
| **ジャンプ** | `Space` |
| **しゃがむ（落下防止）** | `Shift` |
| **ブロック破壊** | 左クリック |
| **ブロック設置** | 右クリック |
| **ブロック横伸ばし設置（アシスト機能）** | ブロック上面の端（フチ）を狙って右クリックすると、側面を見なくても水平方向にブロックを伸ばして設置可能 |
| **ブロック選択** | `1` 〜 `8` キー / マウスホイール |
| **チャット入力** | `Enter` / `T` |
| **掲示板を開く** | 3D掲示板に照準を合わせて左クリック |
| **メモ設置** | ブロックの面に照準を合わせて `M` |
| **メモ閲覧** | 貼られているメモに照準を合わせて左クリック |
| **メモ・掲示板投稿の削除** | 閲覧画面・一覧内の「🗑️ 削除」ボタン（作成者のみ表示） |

## 📌 今後の改善予定

現時点で未実装の項目および今後の改善候補は以下の通りです。

- **キー・プレイヤー情報の管理方法の改善**: 現在は簡易的に `localStorage` のキーとプレイヤー名を用いて作成者判定を行っているため、ブラウザデータ消去時や別端末からでも同一プレイヤーとして扱える仕組みの検討。
- **モバイル・タッチデバイス対応**: 現在はPCブラウザ（キーボード＋マウス操作）を前提としたUI・操作系になっているため、タッチ操作への対応。
